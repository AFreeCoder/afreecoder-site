今天有个朋友问我，为什么 Codex 的额度用得这么快，才 2 天就用完了？他是 Pro 会员（100 美元/月）。

跟他沟通了一下，发现他开着极速模式，思考等级默认拉到最高，还频繁用生图功能。难怪消耗那么快。

所以今天就分享几种节省 token 的小技巧。

*（如果你还分不清 ChatGPT、Codex 等模式的区别，或者不清楚额度怎么算，可以直接滑到文末，看我之前写的两篇文章）*

## 技巧 1：关闭 fast 快速模式

Codex 有个极速模式，打开之后，模型名称前面会多一个闪电标记。

![](https://tjjsjwhj-blog.oss-cn-beijing.aliyuncs.com/article-publish-assistant/98d7bad14e4a5d18d027879c351345b39c7c43068ae61fedb7cd39a760c9d87d.png)

这个模式的意思是：打开之后，模型的回复速度、任务执行速度是标准模式的 1.5 倍，但额度消耗的速度是 2 倍（官方这里有点鸡贼，只含糊说“用量更多”，不明说是 2 倍，生怕你不敢开）。

换句话说，快速模式下**速度增加 50%，额度消耗却增加 100%**。

所以除非 token 多得用不完，完全没必要开。我更倾向于开多个会话、多个任务并行执行来提高整体速度。

*注：数据来源 https://learn.chatgpt.com/docs/agent-configuration/speed*

## 技巧 2：选用合适的模型

下表是 Codex 中不同模型的额度消耗速度，单位是**每 100 万 token 消耗多少 credits**：

| 模型                | 输入  | 缓存输入 | 输出  | 相对 Sol 的粗略倍率      |
| ----------------- | --- | ---- | --- | ----------------- |
| **GPT-5.6 Sol**   | 100 | 10   | 500 | **1×**            |
| **GPT-5.6 Terra** | 50  | 5    | 300 | 大约 **0.5–0.6×**   |
| **GPT-5.6 Luna**  | 5   | 0.5  | 30  | 大约 **0.05–0.06×** |

可以看到，GPT-5.6-Sol 的额度消耗大约是 GPT-5.6-Terra 的 2 倍、GPT-5.6-Luna 的 20 倍。

官方建议是：**Sol 适合复杂、开放式、界定不清的工作；Terra 是日常工作的全能主力；Luna 适合需求明确、可重复执行、大批量的任务**。

*注：数据来源 https://learn.chatgpt.com/zh-Hans/docs/pricing*

## 技巧 3：选择合适的思考等级

从 GPT-5.6-Sol 开始，官方把模型的思考等级划分得很细，一共 6 档：

- 低（Low）——明确的小任务
- 中（Medium）——**官方默认等级**，日常主力
- 高（High）——难一点的开发/排错
- 极高（Extra High）——很复杂或者高风险问题
- 最高（Max）——少数真正棘手的问题
- Ultra——多个 Max 并行处理

官方口径里明确提到**推理强度越高，通常会更慢、消耗更多 token**，但没有给出固定的倍率表。思考等级控制的其实是**最多愿意花多少推理预算**。

而绝大部分日常任务，用官方默认的 Medium 档位完全够用。

另外，根据官方的评测，GPT-5.6-Sol 和 GPT-5.6-Terra 在大部分场景下差距都不大，只有在吃模型能力上限的场景里，比如极难的抽象推理、网络安全、computer use、长链条复杂规划、高难数学，用 GPT-5.6-Sol 才有明显收益。

所以最终的推荐原则是：**默认用 GPT-5.6-Sol Medium，觉得效果不够就往上提思考等级；觉得效果绰绰有余，就换成更省的 GPT-5.6-Terra Medium，不够用再逐级往上提**。

## 技巧 4：删除不必要的 skill

这个观点在之前的文章 [一个任务烧掉 5 亿 token：GPT-5.6-Sol 失控复盘](https://mp.weixin.qq.com/s/rExTpk3wf_J46HryEyKasg) 中提过：随着模型能力增强，很多用来约束模型行为的通用 skill（比如 superpowers），对模型可能起到负优化的作用。通用类的 skill 越多，越容易出问题。

就好比一个技术顶尖的大佬，你给他一个任务，让他自行完成，他会基于自身的实践经验以及深厚的技术能力，把任务完成得很漂亮。

但如果你给他强加各种规范约束、指导意见（skill），这些规范和意见之间甚至还互相冲突，那最后的任务效果必然大打折扣，还会白白消耗很多时间和资源（token）。

**真正有价值的 skill，是从自己业务里抽象出来的流程和经验**，这些是大模型本身不具备、但完成任务又必须知道的东西。

## 技巧 5：慎用 computer use

computer use 是 Codex 最先推出的一个能力，简单来说，就是通过屏幕识别来操作你电脑上的各个软件。

理想情况下，Codex 完全可以代替人操作电脑上的任何软件。但现实是这个能力还不够成熟，它极度依赖截屏和图片识别，精度又不够高，一旦识别不准就会反复尝试，token 消耗特别快。

## 技巧 6：使用内置浏览器和 Chrome Codex 插件

虽然上面提到要慎用 computer use 能力，但是如果操作浏览器的话，消耗的 token 其实没有那么多。

通过 Codex 操作浏览器有好几种方案：第一种是用 Codex 内置的浏览器；第二种是用 Codex 官方为谷歌浏览器开发的插件（也叫 Codex）；第三种是用第三方工具，比如 Browser Use、Playwright MCP 等。

显然，这里应该尽量用内置浏览器和 Chrome Codex 插件。用法很简单，在对话框里直接说用内置浏览器，或者 @Chrome 就行。

## 技巧 7：使用 ChatGPT 生成图片

生成图片是很多人会忽略的一个点。

Codex 或者 Work 模式用多了之后，会下意识地忘掉 ChatGPT 的存在，像图片生成这种 token 消耗特别多的任务也顺手丢给 Codex，一两天就可能把周额度用完。

在之前的文章 [一文讲清楚 ChatGPT、Codex 中的额度到底是多少，怎么回事？](https://mp.weixin.qq.com/s/Ozt8rzTzw9uBv5QsJZTjsQ) 中提到过，ChatGPT 和 Codex 的额度是独立的。

因此，一个节省 token 的技巧就是在 ChatGPT 中生成图片，作为素材放到 Codex 的项目中。

## 技巧 8：搭配 ChatGPT 使用

技巧 8 和技巧 7 是同一个思路。

因为 ChatGPT 和 Codex 的额度是独立的，所以很多不需要跑代码、调试测试的环节，比如需求分析、方案设计，都可以放到 ChatGPT 里做。

网上还有一种思路，是通过 MCP 工具让 ChatGPT 访问本地电脑环境，间接获得操作电脑的能力，有精力的话可以去搜一搜。

## 最后

其实还有一个技巧没写进上面的清单，就是“**想清楚再做**”。就像打工人吐槽的那样，很多领导自己都没想清楚就瞎指挥，白白折腾底下人的精力，道理是一样的。

Codex 这类 Agent 工具近乎“言出法随”，大家越来越倾向于边做边改，而不是先把需求边界、技术约束、测试范围等想清楚了再动手。但是“**想清楚**”本质上是对使用者综合素质的极高要求，也就谈不上技巧两个字了。

上面这些技巧，都是我在实际使用中验证过的，真实有效。如果你还有更好的方法，欢迎讨论。
