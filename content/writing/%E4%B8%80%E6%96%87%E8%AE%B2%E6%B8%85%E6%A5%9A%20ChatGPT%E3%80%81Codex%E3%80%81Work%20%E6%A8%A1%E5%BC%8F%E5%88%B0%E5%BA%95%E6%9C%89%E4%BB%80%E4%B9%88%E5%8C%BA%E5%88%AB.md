最近我发现，有很多 ChatGPT 用户还不知道 Codex 是什么、Work 模式又是什么。甚至还有一些用户听说了这些概念之后，来问我 Codex 怎么用，能不能给他们做个培训。

所以今天这篇文章，就来彻底讲清楚这三个东西到底是什么、有什么区别、怎么用。

ChatGPT 现在是一个统一入口，里面有三种使用方式。Chat 负责聊天，Codex 负责写代码，Work 负责处理日常工作。

在讲具体区别之前，先聊一下这些产品是怎么演变过来的。理解了历史，区别自然就清楚了。

# 先讲一下历史

## 聊天机器人阶段

2022 年底，大模型刚出来的时候，一个核心问题是，这么强的技术，到底以什么产品形态面向用户？

OpenAI 选择了聊天机器人，产品名字就叫 ChatGPT，Chat 是聊天，GPT 是背后的模型。

这个选择非常成功。ChatGPT 上线两个月就突破了 1 亿用户。在很长一段时间里，大众认知里的"AI"就等于"聊天机器人"。

## Agent 工具阶段

后来模型越来越聪明，大家发现一个问题，光聊天不够用。

你让它帮你写一段代码，它确实能写出来，但你得自己复制到编辑器里、自己跑、自己调试、遇到报错再贴回去问它。整个过程还是人在干活，AI 只是在旁边给建议。

于是一类新产品出现了，叫 Agent 工具。它能真正动手，读电脑上的文件、写代码、运行命令、操作浏览器、调用外部工具。只要说清楚任务，它就在后台独立完成。

最早把这件事做出来的是 Anthropic 的 Claude Code。它在编程场景率先实现了代码的自动编写、自动运行、自动调试，写完就跑、报错就修，不再需要人手动复制粘贴。OpenAI 后来也推出了自己的编程 Agent，就是 Codex。

再后来，大家在使用中发现，这类工具不只在编程场景有用。做数据分析、读写 Excel 和 Word、操控桌面软件、整理邮件，这些日常办公的事情它同样干得不错。于是 Codex 开始从编程往通用办公方向扩展，也就是后来的 Work 模式。

其实它们在产品层面是一回事，同一个 Agent 框架，只是背后的工程实现侧重点不同，一个更擅长编程，一个更擅长日常办公。

## 产品合并阶段

在 OpenAI 内部，之前 ChatGPT 和 Codex 是两个独立产品，各有各的团队和入口。

2026 年 5 月，OpenAI 内部经过一番取舍，决定将这两个产品合二为一。ChatGPT 和 Codex 团队合并，统一交给联合创始人 Greg Brockman 负责。7 月，正式将 Codex 合入 ChatGPT 桌面端应用，统一叫 ChatGPT。

所以现在的局面是，不再有单独的 Codex 应用。打开 ChatGPT，里面就能直接切换 Chat、Work、Codex 三种模式。在手机端，ChatGPT 除了可以选择聊天，也可以选择 Work 模式。在桌面端，则可以在 Chat、Work 和 Codex 三种模式之间切换。

简单介绍下三种模式。

> **Chat 模式**：对话为主，你问他答。他只是给建议、给方案，实际任务执行还需要自己来。
> **Work 模式**：你给他一个数据分析的任务，他能直接读取本地的 Excel 文件，分析数据，产出图表等等。一句话理解就是：**凡是人能在电脑上执行的任务，它基本上都能做到。**
> **Codex 模式**：针对编程场景进行优化过的特殊 Work 模式。Work 模式能做的，它也能做。

# 怎么选

判断标准很简单，问自己两个问题。

**第一，这件事需要"聊"还是需要"做"？**

需要聊，用 Chat。比如"帮我解释一下什么是 REST API"、"这段话帮我翻译成英文"。

需要做，用 Codex 或 Work。比如"把这个函数重构一下并跑通测试"、"帮我把这三份 Excel 汇总成周报"。

**第二，如果需要"做"，是写代码还是其他工作？**

写代码用 Codex 模式。其他工作用 Work 模式。

当然，实际使用中没有那么死板。Chat 也能写代码片段，Codex 模式也能顺便改文档。但上面这个判断逻辑能帮你在大多数情况下做出合理选择。

# 额度怎么算

这里有一个容易搞混的地方。**Chat 的额度和 Codex / Work 的额度是分开的。**

你在 Chat 里聊天消耗的额度，不影响你用 Codex 和 Work 做任务的额度。反过来也一样。

但是 **Codex 模式和 Work 模式的额度是共享的**。用 Codex 写代码消耗的额度，和用 Work 做办公任务消耗的额度，来自同一个池子。

目前 Plus 会员是一个计价单位，PRO 100 会员在 Codex 中的额度是 Plus 的 5 倍，PRO 200 会员在 Codex 中的额度是 Plus 的 20 倍。
